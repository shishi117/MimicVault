# MimicVault 初期設定手順

拡張機能の永続インストールと companion アプリをセットアップする手順です。対象は **Windows** のみです。
companion アプリは **exe版のみ動作確認済み**のため、拡張機能・companion ともに Windows（ESR / Developer
Edition）前提で運用しています。companion アプリ自体の仕様は
[コンパニオンアプリ.md](コンパニオンアプリ.md) を参照してください。

セットアップ用の `.bat` ファイルはすべて `scripts/` フォルダにまとめています。

---

## 1. 前提ツールの導入

拡張機能の永続インストールには **Firefox（ESR / Developer Edition）** と、XPI ビルドに使う **web-ext**
（Node.js / npm 経由で導入）が必要です。companion アプリの exe を**自分でビルドする場合のみ**、
**Bun** と **FFmpeg（同梱用バイナリ）** も必要です（ビルド済みの配布物をそのまま使うだけなら 1.4・1.5 は
不要です。4章参照）。すでに導入済みの場合はこの章を飛ばしてください。

> **Node.js / npm と Bun はまとめて導入できます**: `scripts\setup.bat` を実行すると、
> 未導入の場合は自動でインストールします（詳細は 1.2・1.4 参照）。

### 1.1 Firefox（ESR / Developer Edition）の導入

| Firefox 版 | 未署名拡張の永続インストール |
|---|---|
| **ESR** | ✅ 可 |
| **Developer Edition** | ✅ 可 |
| Release（通常版） | ❌ 不可 |

MimicVault は未署名（ID `mimicvault@local`）のため、通常版（Release）では動作しません。
ESR または Developer Edition を用意してください。

**ダウンロード**

- ESR: https://www.mozilla.org/firefox/enterprise/ の「Firefox ESR をダウンロード」から入手します。
- Developer Edition: https://www.mozilla.org/firefox/developer/ から入手します。

**インストール**

ダウンロードした `.exe` を実行し、インストーラーの指示に従います。

**未署名拡張を許可する設定（一度きり）**

1. アドレスバーに `about:config` と入力して Enter を押します。
2. 「リスクを承知の上で使用する」ボタンをクリックして警告画面を通過します。
3. 上部の検索欄に `xpinstall.signatures.required` と入力します。
4. 表示された項目の値（Boolean）をダブルクリックして `true` → `false` に切り替えます。

> この pref はセキュリティ設定のため、後述の enterprise policy では配布されません。必ず手動で設定してください。

### 1.2 Node.js / npm の導入

XPI ビルド（`web-ext`）に使うランタイムです。**v14 以上**が必要です。

公式サイト https://nodejs.org/ から LTS 版のインストーラー（`.msi`）をダウンロードして実行、
もしくは `winget install OpenJS.NodeJS.LTS` を実行します。

> `scripts\setup.bat` を実行すると、Node.js が無い場合はこの `winget install` を自動で実行します
> （`winget` 自体が無い場合はエラーで止まるので、その場合は上記を手動で行ってください）。
> インストール直後はこのターミナルの PATH が更新されないため、`setup.bat` は一度終了します。
> 新しいターミナルを開いて `scripts\setup.bat` を再実行してください。

**確認**

```bash
node -v
npm -v
```

### 1.3 web-ext の導入

拡張機能の lint / 開発起動 / XPI ビルドに使う Mozilla 公式 CLI です。`package.json` の
`devDependencies` に含まれているため、個別インストールは不要です。1.2 で Node.js / npm を
導入済みなら、リポジトリのルートで `npm install` するだけで同時に入ります。

1. ターミナル（コマンドプロンプトまたは PowerShell）を開きます。
2. `cd` でリポジトリのルート（`package.json` や `manifest.json` があるフォルダ）へ移動します。
   ```bash
   cd \path\to\MimicVault
   ```
3. `npm install` を実行します。`package.json` の `devDependencies` に書かれたツール（`web-ext` など）を
   自動でダウンロードし、同じフォルダ内の `node_modules` に格納します。
   ```bash
   npm install
   ```

> 上記 1〜3 の代わりに、`scripts\setup.bat` をダブルクリックするだけでも
> 同じ `npm install` を実行できます。`setup.bat` は Node.js / Bun が未導入なら先にそれらも
> 自動インストールします（詳細は 1.2・1.4 参照）。

**確認**

`npx` は `node_modules` にインストールされたコマンドを直接実行する仕組みです（PATH設定は不要）。

```bash
npx web-ext --version
```

バージョン番号（例 `8.10.0`）が表示されれば導入完了です。

> `npm run lint` / `npm run run` / `npm run build` が内部で `web-ext` を呼び出します
> （共通設定は `web-ext-config.mjs`）。

### 1.4 Bun の導入（companion exe をビルドする場合のみ）

`companion/app.js` を単一 exe にコンパイルするために使用します。ビルド済みの exe を受け取って
使うだけの利用者には不要です（4章の配布物をそのまま使えます）。

```powershell
powershell -c "irm bun.sh/install.ps1 | iex"
```

- インストーラーが PATH への追加を自動で行いますが、反映されない場合は新しいターミナルを開き直してください。

> `scripts\setup.bat` を実行すると、Bun が無い場合はこのインストールコマンドを自動で実行します。
> この場合も PATH 反映のため、新しいターミナルで `scripts\setup.bat` を再実行してください。

**確認**

```bash
bun --version
```

> Bun を使いたくない場合は Node.js 公式の
> [SEA（Single Executable Applications）](https://nodejs.org/api/single-executable-applications.html)
> でも同様の exe を作成できますが、手順が増えます。

### 1.5 FFmpeg（同梱用バイナリ）の取得（companion exe をビルドする場合のみ）

exe 版は `ffmpeg.exe` を**同梱して配布**するため、ビルドする人のマシンに FFmpeg をインストールする必要は
ありません。配布物に含める `ffmpeg.exe` を次の手順で入手します。

1. FFmpeg の Windows 用 static ビルドを配布しているサイト（[gyan.dev](https://www.gyan.dev/ffmpeg/builds/) や
   [BtbN/FFmpeg-Builds](https://github.com/BtbN/FFmpeg-Builds/releases)）から `release full` 版の zip を
   ダウンロードします。
2. zip を展開し、中の `bin\ffmpeg.exe` を取り出します。
3. この `ffmpeg.exe` を 3章で同梱用に使用します。

## 2. 拡張機能の永続インストール（enterprise policy）

Firefox の **enterprise policy**（`ExtensionSettings` → `force_installed`）を使い、未署名の
MimicVault 拡張機能を「企業ポリシーにより追加」として永続的に常駐させる手順です。
`web-ext run` の一時読み込みと違い、**Firefox を再起動しても消えません**。

### 2.1 前提

- 1.3 で web-ext を導入済みであること（`npm install` 済み。XPI ビルドに使用）

### 2.2 インストール実行

インストーラが以下を自動で行います。

1. 同じ配置先に既存の永続化登録（`policies.json` / XPI）があれば削除（二重登録防止）
2. `web-ext build` で XPI をビルド
3. XPI を安定パスへ配置（`%APPDATA%\MimicVault\mimicvault.xpi`）
4. `deploy/policies.json` のプレースホルダ `__XPI_PATH__` を実パスに置換し、
   Firefox の policies ディレクトリへ配置（永続追加 + プライベートウィンドウ許可）

```bat
:: 省略可（Developer Edition の既定パスを使用）
scripts\install-policy.bat

:: 別の Firefox を使う場合は実パスを指定（角括弧・山括弧は付けない）
scripts\install-policy.bat "C:\Program Files\Firefox Developer Edition\distribution"
```

- 第1引数を省略すると `C:\Program Files\Firefox Developer Edition\distribution` を既定にします。
- policies.json の書き込みに**管理者権限が必要な場合があります**。

### 2.3 反映と確認

1. **Firefox を再起動**します。
2. `about:addons` に MimicVault が **「企業ポリシーにより追加」** として表示されれば成功です。
3. `about:policies` でも配置内容を確認できます。

### 2.4 配布される設定内容

`deploy/policies.json`（配置時に `__XPI_PATH__` が実パスに置換されます）:

```json
{
  "policies": {
    "ExtensionSettings": {
      "mimicvault@local": {
        "installation_mode": "force_installed",
        "install_url": "file://__XPI_PATH__"
      }
    },
    "Preferences": {
      "extensions.allowPrivateBrowsingByDefault": { "Value": true, "Status": "locked" }
    }
  }
}
```

- `force_installed`: 拡張を永続追加（ユーザーによる削除も禁止）
- `allowPrivateBrowsingByDefault=true`: プライベートウィンドウでの実行を全体許可
  （`webRequest` でメディア検出するために必要）

### 2.5 アップデート手順

拡張のコードを更新したら、**インストールと同じコマンドを再実行**するだけです。
新しい XPI が同じパスに上書き配置され、Firefox 再起動で反映されます。

```bat
scripts\install-policy.bat ["<Firefox>\distribution"]
```

### 2.6 アンインストール

1. 配置した `policies.json` を削除します（配置先はインストール時のログに表示されます）。
   - 例（既定）: `C:\Program Files\Firefox Developer Edition\distribution\policies.json`
2. Firefox を再起動すると `about:addons` から MimicVault が消えます。
3. 配置済み XPI が不要なら削除します。
   - `%APPDATA%\MimicVault\`

> companion アプリ（Native Messaging）のインストール・アンインストールは次章、
> および [コンパニオンアプリ.md](コンパニオンアプリ.md) を参照してください。拡張機能とは別管理です。

### 2.7 トラブルシューティング

| 症状 | 原因 / 対処 |
|---|---|
| `about:addons` に出ない | `about:policies` で policy が読まれているか確認。Firefox を完全再起動したか確認。 |
| 「署名されていないため無効」 | `xpinstall.signatures.required=false` が未設定。1.1 節の手順を実施（ESR / Developer Edition のみ有効）。 |
| Release 版で入らない | 仕様。Release は未署名を拒否。ESR / Developer Edition を使用。 |
| `web-ext-artifacts/*.zip が見つかりません` | ビルド失敗。ルートで `npm install` 後、`npm run build` が通るか確認。 |
| policies.json を書き込めない | 配置先が権限不足。管理者権限で実行、またはプロファイル用 `distribution` を第1引数で指定。 |
| プライベートウィンドウで検出しない | policy 未反映。再起動後、`about:addons` →「プライベートウィンドウでの実行を許可する」を手動確認。 |

## 3. companion アプリ（exe版）のビルド

[Bun](https://bun.sh/) を入れて:

```
scripts\build.bat
```

（中身は `bun build ..\companion\app.js --compile --target=bun-windows-x64 --outfile ..\companion\mimic-vault.exe`
の1行です。ビルドされた exe は `companion\` フォルダに出力されます。）

1.5 で取得した `ffmpeg.exe` を、`companion\mimic-vault.exe` と**同じフォルダ**（`companion\`）に置きます。
companion は同フォルダの `ffmpeg.exe` を自動で見つけます（無ければ PATH 上の ffmpeg にフォールバック）。

> **一括更新**: 上記（`ffmpeg.exe` の取得〜ビルド〜4章のインストールまで）を1つにまとめた
> `scripts\update.bat` もあります。Firefox を終了させた上で、`ffmpeg_deploy.bat`（未取得時のみ
> ffmpeg.exe をダウンロード）→ `build.bat` → `install.bat`（`companion\` を対象に指定）を順に実行し、
> 最後に Firefox を再起動します。companion のコードを更新した際の再ビルド・再インストールに使えます。

## 4. 配布・インストール

配布用フォルダに、`companion\mimic-vault.exe` / `companion\ffmpeg.exe` / `companion\native-manifest.json` と
`scripts\install.bat` を**コピー**してまとめます（`install.bat` の実体は `scripts\` にありますが、
配布先では exe 等と同じフォルダに置く必要があるため、コピーして1フォルダ化します）。
利用者はそのフォルダの `install.bat` を実行するだけです（引数なしなら自分と同じフォルダを見ます。
管理者権限不要、`HKCU` に登録）。

> 配布時の注意: 署名なし exe は Windows SmartScreen の警告が出ることがあり、コンパイル済み JS の exe は
> まれにウイルス対策ソフトに誤検知されます。広く配るなら **コード署名証明書**の利用を検討してください。

インストール後、Firefox を再起動すると拡張機能のポップアップ右上に companion 接続インジケータが表示されます。
companion アプリの仕様・アンインストール手順は [コンパニオンアプリ.md](コンパニオンアプリ.md) を参照してください。

## 5. 一括セットアップ（install-all.bat）

`scripts\install-all.bat` を実行すると、1〜4章の主要な手順を次の順でまとめて実行できます
（各バッチの内容を1つに統合したものではなく、同じ `scripts\` フォルダ内の `setup.bat` /
`update.bat` / `install-policy.bat` を順番に呼び出すだけです）。

1. `setup.bat`（1章: Node.js/npm・Bun が未導入なら導入 → `npm install`）
2. `update.bat`（3〜4章: companion exe のビルド・インストール。対象は `companion\`）
3. `install-policy.bat`（2章: 拡張機能の永続インストール）

```bat
scripts\install-all.bat

:: 別の Firefox distribution に配置する場合（install-policy.bat への引数）
scripts\install-all.bat "C:\Program Files\Firefox Developer Edition\distribution"
```

> `setup.bat` が Node.js / Bun を新規インストールした場合、PATH 反映のためそこで一度停止します
> （画面の指示に従って新しいターミナルで `install-all.bat` を再実行してください）。
> 2・3番目のステップは実行結果を正しく終了コードに反映しないため、正常終了に見えても
> 各ステップの `[ERROR]` 表示が出ていないか画面を確認してください。
